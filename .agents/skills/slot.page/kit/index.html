Not HTML at all when the demo would have to reimplement the product's own complex live state (the situation head is the example): prototype on the real route instead, where the state is already true.

Make one real

1Copy a template. Replace its fixture with real data: python build.py review.html data.json out.html. The JSON comes from a small extractor run over real artifacts, never typed by hand; build fails fast when a key the template reads is missing, stamps provenance, and inlines local images.
2Keep the product's real rules and messages where they are known. Anything invented carries standIn and is drawn with the dashed stand-in mark, naming what replaces it.
3Edit the pure module first (lifecycle, verbs, reduce, or the sandbox's MACHINE block), then the drawing. Never mutate state outside reduce.
4Prove it headless: python check.py out.html fails on any JS error and runs the page's own window.__walk(). The template walks assert fixture ids; adapt the walk to your data, or use --no-walk for errors only. With no arguments it checks all four templates and that their kernels are still identical.
