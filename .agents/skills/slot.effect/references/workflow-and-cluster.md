# Lessons from the workflow and cluster experiment

[ADR 0050](../../../../docs/adr/0050-workflow-owns-durable-commands.md) records the rejected replacement for the action journal. These notes describe the Effect 4.0.2 pin. The retained experiment is at `e9f9eaaf`. Its later source integrity changes were saved as `source-integrity-in-progress.patch` and were still in progress.

- `Workflow.executionId` hashes the workflow tag and its idempotency key. Bind that key to the admitted payload before invoking the engine if a changed payload under the same key must conflict. (`effect/src/workflow/Workflow.ts`, `e9f9eaaf:ts/apps/host/src/commands/service.ts`.)
- `Workflow.execute(payload, { discard: true })` returns the execution ID without waiting for the result. Give the caller a separate way to observe completion. (`effect/src/workflow/Workflow.ts`, `e9f9eaaf:ts/apps/host/src/commands/service.ts`.)
- `Activity.idempotencyKey(name)` binds the workflow execution ID and the activity name. It includes the attempt number only when `includeAttempt` is enabled. (`effect/src/workflow/Activity.ts`, `e9f9eaaf:ts/apps/host/src/commands/program.ts`.)
- Give each repeated step a stable occurrence name, because the cluster activity envelope uses `name/attempt` as its primary key within a workflow execution. (`effect/src/cluster/ClusterWorkflowEngine.ts`, `e9f9eaaf:ts/apps/host/src/commands/activity-results.ts`.)
- Expect `ClusterWorkflowEngine` to reset and rerun a suspended Activity attempt in its replay loop. The owner of an external effect still decides what can be safely invoked again. (`effect/src/cluster/ClusterWorkflowEngine.ts`, [ADR 0050](../../../../docs/adr/0050-workflow-owns-durable-commands.md).)
- The activity RPC carries `withTransaction` from the Activity's `ClusterSchema.WithTransaction` annotation. Use it for effects covered by the runner's SQL transaction. (`effect/src/cluster/ClusterWorkflowEngine.ts`, `e9f9eaaf:ts/apps/host/src/commands/program.ts`.)
- Check storage custody and schema before building `ClusterWorkflowEngine` and its SQL `SingleRunner`. A replay-capable layer can start reading or dispatching as soon as it starts. (`60f08cc2:ts/apps/host/src/commands/layer.ts`.)
- Cluster SQL stores a composed deduplication key directly up to 255 characters. It hashes a longer key, so use the storage API when the raw key may exceed that boundary. (`effect/src/cluster/SqlMessageStorage.ts`, `source-integrity-in-progress.patch`.)
- Keep cluster request and reply IDs exact when reading SQL. The storage implementation uses `SqlClient.SafeIntegers`, and the experiment casts those IDs to text in its inspection query. (`effect/src/cluster/SqlMessageStorage.ts`, `source-integrity-in-progress.patch`.)
- `requestIdForPrimaryKey` finds a request by deduplication key. A reader that needs durable evidence also checks the persisted address, tag, occurrence, attempt and reply identity. (`effect/src/cluster/MessageStorage.ts`, `source-integrity-in-progress.patch`.)
- Inspect the message and replies in one SQL transaction. A terminal `WithExit` reply must agree with the message's `processed` flag, `last_reply_id` and request ID. (`effect/src/cluster/SqlMessageStorage.ts`, `54b2140e:ts/apps/host/src/commands/activity-results.ts`.)
- Decode the stored transport exit with the codec for `Schema.Exit(Workflow.Result(...), ...)`. Only a `Complete` result carries the Activity's own typed exit. (`54b2140e:ts/apps/host/src/commands/activity-results.ts`.)
- Separate a never-enqueued Activity from a completed Activity with a missing reply. A staged semantic step may have neither a message nor a reply, while a processed message with a missing terminal reply loses its evidence. (`source-integrity-in-progress.patch`, `command-foundation.test.ts`, `PUR-EVID-04`.)
