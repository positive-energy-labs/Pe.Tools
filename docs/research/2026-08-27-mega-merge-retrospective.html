The ideas that survived contact with the code

1 · Native authority beats a local shadow

Pea no longer maintains a second thread/transcript truth where Mastra already owns one. The stable identity is the native server session keyed by durable thread coordinates; assistant-ui renders it. Delete projection and wire layers before inventing synchronization between two authorities.

2 · A route document is not page memory

The portable document owns facts another participant must see: binding, snapshot, staged intent, revision, receipts. The route store owns local interaction: hover, sorting, pane state, busy state. This boundary makes human, agent, tab, and host collaboration possible without putting the React tree in charge.

3 · Concurrency without locks

Every external write carries the revision it was based on. Every external command also carries a client-minted request ID. The server serializes, refuses stale work, persists a canonical receipt, replays duplicate requests, and keeps an outcome-unknown crash barrier. A CRDT would be more machinery and less authority.

4 · One outcome language, many route stores

The routes do not need one global store. They need one typed grammar: busy, applied, refused, error, outcome unknown, plus the same icon, color, copy, receipt and placement rules. The critical constraint is that kind survives every adapter; flattening it into an Error destroys the visual language.

5 · Commands are writes

A command is not a side channel. It shares revision admission, idempotency, receipts, typed refusal and replay with patch application. Its success history is also custody: only a successful command may become lastCommand or arm the next destructive verb.

6 · Generate authority; never count it by hand

The true operation change was 56 → 66, exactly ten Takeoffs operations. The requested 66 → 76 double-counted the promotion. Catalog generation, key-set diffs, and drift gates are stronger than acceptance prose—and should produce the number themselves.

7 · Thin routes are an architectural signal

routes/families.tsx fell from 1,478 to 38 lines. The useful shape is route shell → feature workspace/view → route store → portable document/host. Moving code alone is not victory, but it makes authority and hotspots legible enough to improve.

8 · Proof must cross the user-visible seam

Typecheck and deterministic suites were green while the real UI painted a stale-revision refusal as generic error and emitted an unhandled rejection. The browser race found what unit proof could not; the critic then found a destructive-arming regression the browser script did not ask about.

How the verdict was earned

  1. Pre-flight and ruled branch fixes

    Uncommitted Flow work was committed narrowly. REVIEW §3 fixes landed on their owning branches before integration. The first merge commit carried the §8 verdicts as ledger rows.

  2. Cleanroom merge

    Native thread/session authority and explicit capability denial landed. Critic KILLs forced compatibility and provider-error repairs before adoption.

  3. Route-workspace merge

    The first candidate was killed because two TanStack generators rewrote one tracked route tree differently and because five hard-zero design laws were silently weakened. Repair aligned generator custody and made the design debt explicit.

  4. Concurrency and typed outcomes

    expectedRevision, requestId, durable receipts, replay, and outcome-unknown crossed contracts, runtime, HTTP, route stores and MCPs. A first critic caught both a red full web test and successful oversized results being discarded.

  5. All-route language pass

    Four bespoke flatteners were deleted for one carrying error/result seam. Seven route consumers received the same RouteWriteKind vocabulary.

  6. Real two-tab falsifier at 9f4c9db

    Tab A won at revision 0 → 1. Tab B correctly failed to overwrite—but the DOM said data-kind="error" and the promise rejection was unhandled. Deterministic green was insufficient.

  7. Root repair, then critic KILL

    Returning the original typed result fixed the DOM and rejection. The critic traced the altered control flow further: a refused preview now entered lastCommand, marked the profile reviewed, and armed Apply.

  8. One-line success-custody repair

    if (result.ok) at the only lastCommand writer made the unsafe state unrepresentable for every consumer. The exact-head browser race then rendered refused, kept the losing draft, showed Changed elsewhere, preserved the winner, and recorded zero unhandled rejections.

  9. Exact-head closure

    Five TypeScript compiles, web 51 files / 325 tests, runtime 5 / 30, host 9 / 54 (+2 skipped), MCP 11 / 46 (+1), agent-contracts 10 / 21, guards 2 / 16, stable route generation, 66-op codegen, and full pnpm ready. Final Opus verdict: Adopt.

The essential falsifier: a correct server refusal is not sufficient. If an adapter erases its kind, the UI tells a different story. If a failure enters success history, the next action can become unsafe even though the refusal itself looks right.

Residual proof gap: the one-line lastCommand rule has no direct automated guard. Review found and repaired it; a roughly 10-line store test should pin “non-ok leaves lastCommand unchanged; ok records it.” This is a product gate, not a new framework.

Proposed Surface Philosophy changes

SURFACE-PHILOSOPHY.md already says one vocabulary, refuse rather than act unreliably, silent refusal looks like a vanished edit, ceremony follows blast radius, and the visible model must be drivable outside the component tree. The merge proved four concise additions. Keep protocol mechanics in the design-system ledger; put only user-visible laws in the philosophy.

Add to §1 · State and vocabulary

Typed outcomes are end-to-end language

One write has one kind from admission to receipt. Applied, refused, failed, and outcome unknown are different truths; no adapter may flatten them into “error.” The typed kind drives the words, icon, colour, and next available verb on every surface.

Why: the final browser falsifier existed solely because the store and server knew refused while the workspace adapter erased it.

Add to §3 · Honesty

A refused write preserves the local draft

A conflict refuses the commit, not the user’s thought. Keep the local draft, show the newer shared facts, say “changed elsewhere,” and make re-read or retry explicit. Never silently overwrite either side.

Why: this is the concrete multi-tab form of the existing “silent refusal reads as an edit that vanished” law.

Add to §3 · Honesty

Only success owns success history

A refused or failed command may explain and remain retryable, but it never becomes the last successful command, never satisfies review, and never arms a stronger verb.

Why: the Wave 14 critic proved that “what happened last” and “what succeeded last” are not interchangeable state.

Refine §7 · Route anatomy

One document language, local page memory

A route renders one portable document and one typed write language. Shared facts and staged intent live in the document; hover, sorting, panes, and transient interaction stay local. The component tree renders both and owns neither.

Why: this preserves the existing rule that a route owns its world and host calls without accidentally demanding one global store for products with different commitment models.

Design-system follow-through

  • Add a rendered stale-revision specimen to /design-system: two views at r0, one lands r1, the other retains its draft and renders refused plus Changed elsewhere.
  • Make the specimen assert all typed outcome kinds and next-verb availability. Once rendered, the philosophy can point to it and avoid procedural prose.
  • Close or rewrite ledger rows that still describe refused as a future vocabulary gap; it is now a shipped cross-route spine, while outcome attribution remains legitimately Owed.
  • Do not add a universal route store. The ledger already correctly rules shared vocabulary, not shared commitment state.

Substrate and setup findings

Yes—there were significant non-GUI frictions. They cluster around proof custody and worktree dependency identity, not Revit itself. Three deserve substrate work; several others were repaired inside this merge and should not spawn a second system.

P0

One reliable proof-receipt runner

The final pnpm ready wrapper reached the last success line and returned terminal exit 0, but its Start-Process metadata serialized a blank child ExitCode. That forced forensic adjudication of && semantics and raw logs.

Smallest fix: one repo-owned PowerShell helper that starts a command, waits, then writes command, cwd, start/end, populated exit code, stdout/stderr paths, byte counts and SHA-256. Reuse it for long proof lanes; do not build a generic task engine.

P0

Make operation deltas generated evidence

The goal’s “66 → 76” wording blocked closure even though the authoritative catalog correctly moved 56 → 66. Ten operations were counted twice in prose.

Smallest fix: extend the existing offline catalog check with --base <ref> (or a sibling script) that prints old count, new count, added keys and removed keys. Acceptance should cite that receipt, never handwritten arithmetic.

P1

Worktree dependency wiring: create and verify

A whole shared node_modules tree can make a sibling worktree resolve packages and fonts through the main checkout. The route-generator diagnosis also found two generator versions in the shared pnpm topology. The existing safe recipe—per-entry junctions, with @pe/* pointing into the current worktree—is correct but manual.

Smallest fix: one vp worktree wire command (or script) that creates those junctions and a --check mode that rejects a whole-tree junction, escaped @pe/* realpaths, and mismatched generator realpaths.

P1

Pin success custody with one deterministic test

The only lastCommand writer is now correctly guarded, but no test proves it. This regression can arm a destructive verb, so the test belongs in the deterministic route-store lane.

Smallest fix: one test: a refused command leaves lastCommand unchanged; a successful one records it. No browser harness and no new abstraction.

P2

Promote the two-tab race only after it repeats

The targeted browser lane was uniquely valuable, but full automation would add lifecycle and fixture machinery. Keep the current receipt recipe now. If a second concurrency feature needs it, promote the exact race into one repo-owned browser command.

Trigger: another stale-write or request-replay change that cannot be certified below the browser seam.
