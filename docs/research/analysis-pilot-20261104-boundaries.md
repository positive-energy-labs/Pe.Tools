## Findings

The agent tarball contains four members including built JavaScript and declarations, but no `src`. Its packed manifest still exports `./src/index.ts`. The real import fails with `ERR_MODULE_NOT_FOUND`; kernel-page and route-module subpaths fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`. No tarball was edited, no missing-build failure was manufactured. Source: [ts/packages/agent-contracts/package.json](../../.artifacts/runs/analysis-20261104/boundaries/authority/ts/packages/agent-contracts/package.json), [ts/packages/agent-contracts/vite.config.ts:1](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/packages/agent-contracts/vite.config.ts.html#L1). Manual depth sample: the kernel `RouteModule` contract requires data, schemas, codecs, identities, entries, bodies and artifact, with optional sources (`route-kernel-admission.ts:62`). This makes route authors aware of serialization, identity, transport and admission in addition to the domain body. It also hides important implementation: admitted values carry nominal membership, captured bindings, and frozen data; normal mounting uses an admitted object rather than reimplementing those rules. `families/neutral.ts` isolates host-safe recovery/workState from `FamiliesKernelMatrix` and browser source composition in `families/kernel.ts`. This is a concrete width/consumer-knowledge/hidden-implementation account, not a module-depth score.

## Graph evidence and limits

[Interactive HTML](../../.artifacts/runs/analysis-20261104/boundaries/boundaries.html) and [plain graph JSON](../../.artifacts/runs/analysis-20261104/boundaries/graph.json) drill down package → file → exported/top-level declaration. Each file shows incoming consumers and an expandable dependency tree with cycle markers. The page separates all, production, and runtime-only SCCs. All links open retained baseline snapshots. The page requires no server or remote resources. Browser rendering was not exercised; script syntax and snapshot anchors are checked separately.

AST census uses tracked files, excludes dist, dist-installed, node_modules, .artifacts, bin, obj, generated and vendor paths and generated-name outputs. It separates test/spec/typecheck/fixture paths from production. This is a filename classification, not a semantic assertion that every other file ships. Metrics count top-level declared exports, not expanded barrel exports, parameter burden, or every public member. [Module depth dimensions](../../.artifacts/runs/analysis-20261104/boundaries/module-depth.json) report API width, manifest doors, incoming consumer files/names, and cross-boundary import leakage separately. A 1,256-declaration count for agent-contracts is an authored-source census, **not 1,256 exported npm entrypoints**. Hidden implementation is inspectable through per-file export declarations versus other declarations and caller paths; no claim that a line ratio measures conceptual depth.

Symbol import bindings and lexical imported calls are included. Full semantic symbol edges, dynamic dispatch, JSX uses, alias-flow and reliable call ownership by enclosing symbol are unsupported. HTML says this on the symbol drilldown. The simple resolver supports relative imports, `#/` web aliases, and workspace exports; unresolved/generated targets remain visible but do not enter authored-source SCCs. Type-only per-specifier imports are recognized; mixed imports remain runtime/mixed. Type-only specifiers within re-export declarations have limited classification. SCCs are static relationships, not runtime-execution proof.

## Storage substitution experiment

The production composition injects `RouteDocumentStore` into `RouteWorkspace`: [ts/packages/runtime/src/route-workspace.ts:75](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/packages/runtime/src/route-workspace.ts.html#L75). The path derives from host ownership, not merely USERPROFILE: [ts/apps/host/src/product-paths.ts:30](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/apps/host/src/product-paths.ts.html#L30), [ts/apps/host/src/host-ownership.ts:49](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/apps/host/src/host-ownership.ts.html#L49).

[Probe script](../../.artifacts/runs/analysis-20261104/boundaries/storage.mjs) runs two separate minimal-env processes, A and B, with fresh redirected homes, `PE_LANE=dev`, and no shared module cache. It imports the real production resolver and real file store; asserts initial read is null; writes the same target/route with distinct markers; reads and lists each record; instruments synchronous filesystem writes and asserts every write is under that process's product home. Known-folder subprocess discovery is forbidden by an instrumented `execFileSync`. Both pass. [A output](../../.artifacts/runs/analysis-20261104/boundaries/storage-A.stdout.txt), [B output](../../.artifacts/runs/analysis-20261104/boundaries/storage-B.stdout.txt). This proves this narrow real storage seam; it does not exercise full RouteWorkspace migration, crash recovery, native operations, or every async filesystem call.

Both ordinary and scrubbed test runs redirect HOME, USERPROFILE, APPDATA, LOCALAPPDATA, TEMP/TMP, product home and SDK-home placeholders. Ordinary preserves other inherited variables without printing them; scrubbed retains only OS/PATH tooling essentials. Existing global/setup files then replace product and SDK registry/files/service roots with per-run/per-file temp children. [ts/tests/isolated-home/global-setup.ts:1](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/tests/isolated-home/global-setup.ts.html#L1), [ts/tests/isolated-home/setup.ts:1](../../.artifacts/runs/analysis-20261104/boundaries/source/ts/tests/isolated-home/setup.ts.html#L1). The experiment therefore tests hidden inherited-variable dependencies **under the repository's isolation harness**, not unconfigured first launch. No user Documents or LocalAppData data was read recursively or written by the probes.
