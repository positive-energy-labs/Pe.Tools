# Browser port assessment

Reviewed against [chrome-agent 0.7.1, `ab3f3be6`](https://github.com/captivus/chrome-agent/tree/ab3f3be6ef4c3be85546bf84aa8282b98456b97b) on 2026-10-25. The upstream checkout was fetched before review. This is a comparison of source and bounded local behavior, not a claim of feature parity or general Windows certification.

The port has high value for the user's two goals: typed browser tests and a usable Windows browser capability for Pea. Its strongest changes are the shared TypeScript API, explicit lifecycle ownership, and a required product assertion that has rejected a deliberately broken behavior. The first port carried more of the engine than the agent workflow. The shared guide and `pea browser` entry now address that adoption gap.

## What upstream discovery actually does

Upstream bundles its agent guide as a package resource. CLI help leads to `guide`, which prints the guide or its installed path. Live protocol help supplies method detail, while shell completion offers running instances and browser-reported methods/events. These are complementary discovery layers; the inspected implementation does not automatically register a browser capability in every agent harness. See [guide delivery](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/src/chrome_agent/cli.py#L65-L80), [completion](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/src/chrome_agent/cli.py#L82-L250), and [protocol discovery](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/src/chrome_agent/protocol.py).

The useful method in [upstream's AGENTS.md](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/AGENTS.md) is continuous observation around bounded actions: inspect structured state, act on the real control, then read the outcome independently. It chooses DOM/Accessibility for content, screenshots for appearance, and persistent events for failures and transitions. That is more valuable than a fixed list of CDP commands. Its synthetic-input examples and harness-specific monitoring instructions need adaptation to Pea's trusted-input tests and Windows shell.

Pea now publishes the same [`use-browser` guide](../../../ts/packages/browser/src/guide.ts) to both harness skill roots and the normal `pe_find`/`pe_read` capability path. `pea browser guide` exposes it without a host or browser. Connected `help SESSION Domain.method` provides the second level. One source owns the prose; there is no parallel browser MCP catalog to keep synchronized.

## Which deviations earn their cost

| Area | Local choice | Assessment |
|---|---|---|
| Typed programs | Known CDP command mappings, raw escape hatch, and one inferred JSON evaluator on `BrowserPage` and `CdpClient` | An improvement for tests and larger agent journeys. It removes asserted `read<T>` result shapes. Static types still cannot prove the callback's browser behavior or transfer its closures. |
| Protocol freshness | Live HTTP schema with provenance; explicitly unverified bundled reference when live schema is unavailable | An improvement in honesty. Pinned types/reference data never certify a particular attached Chrome. |
| Lifecycle | Owned/attached custody, exclusive target leases, release versus close, and joined Windows shutdown | Necessary for a shared Windows machine. It makes cleanup rights and retained targets inspectable. Raw browser CDP remains privileged. |
| Shell use | Explicit session/target ids and JSON files/stdin | Safer targeting and reliable PowerShell arguments, with more ceremony than upstream's names, globs, and selector conveniences. That cost is real. |
| Observation | Bounded CLI event stream; persistent subscriptions in the library | Adequate for the current typed journeys. Upstream's interactive multi-event observer remains more convenient for shell investigation. |
| Agent onboarding | Shared guide, bundled skill, and the existing shipped `pea` command | Restores a missing part of the original idea and fits Pea's existing discovery system. A README alone did not provide this route. |
| Other upstream features | No equivalent shell completion, encrypted snapshot/restore workflow, fingerprint profiles, or desktop management | Omitted scope, not automatically improvements. Completion/selector convenience may repay observed shell friction. Snapshot/restore has a separate state and credential lifecycle to own. |

The relevant local owners are [`browser.ts`](../../../ts/packages/browser/src/browser.ts), [`evaluate.ts`](../../../ts/packages/browser/src/evaluate.ts), [`protocol.ts`](../../../ts/packages/browser/src/protocol.ts), [`keeper.ts`](../../../ts/packages/browser/src/keeper.ts), and [`cli-runner.ts`](../../../ts/packages/browser/src/cli-runner.ts). Upstream convenience and observation behavior can be traced in its [CLI](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/src/chrome_agent/cli.py) and [collaboration guide](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/docs/collaboration-guide.md); persistence scope is documented in its [README](https://github.com/captivus/chrome-agent/blob/ab3f3be6ef4c3be85546bf84aa8282b98456b97b/README.md#session-snapshots).

## Value for correctness

The required [`product-selection.test.ts`](../../../ts/tests/e2e/product-selection.test.ts) is the decisive first step. Fixed local navigation data, actual controls, inferred callback results, exact URL membership, rendered chips/crumb, reload, and Back/Forward assert one product contract. A temporary served-code mutation that replaced additive selection with replacement made the normal gate fail; restoring the source returned it to green. The gate is registered in [`verify.ts`](../../../ts/scripts/verify.ts), separate from the longer optional journeys.

This establishes a useful pattern, not broad product coverage. Deterministic fixture inputs and bounded assertions reduce uncertainty; Chrome scheduling, production services, engineering correctness, Revit mutations, and every rendered visual property remain separate claims. More browser infrastructure alone does not add those assertions. Grow the required gate from concrete product failures, calibrating each regression against the broken behavior.

## Evidence and remaining boundary

- Required selection and deliberate failure: `f8e410d3`; receipts under `.artifacts/runs/browser-selection-20261025/`. Public evaluator typing, native exceptions/serialization, and shared required-gate use: `21332aca`; receipts under `.artifacts/runs/browser-evaluate-20261025/`.
- Guide admission, revision hash, publication into both harness roots, and `pe_find`/`pe_read`: [`browser-skill.test.ts`](../../../ts/packages/mcps/tests/browser-skill.test.ts). These prove the discovery adapters over a controlled transport, not an autonomous Pea product conversation.
- Packaged worker dispatch: [`worker.ts`](../../../ts/packages/browser/src/worker.ts) and [Pea main](../../../ts/apps/pea/src/main.ts). A copied `pea.exe` ran outside the checkout with no sibling JavaScript, launched its own browser, read live help, used trusted text/click input, and shut down. Its attachment keeper/guardian preserved a borrowed target and removed its created target. The source Pea command passed the same owned-browser workflow. Evidence: `.artifacts/runs/browser-discovery-20261025/native-cli-proof.json`.
- A fresh reader, given only the guide and public CLI, completed trusted form entry, independently confirmed rendered submission, and stopped its session. It exposed an unclear per-command `--home` requirement and rejection of PowerShell's UTF-8 BOM parameter files. The guide now states the requirement; [`cli.test.ts`](../../../ts/packages/browser/tests/cli.test.ts) rejects the old parser and passes the BOM-tolerant parser. The bundled library's worker and async evaluator also passed a native document-readiness probe. Evidence: `.artifacts/runs/browser-discovery-20261025/`.
- A second fresh reader used the final guide and rebuilt executable to complete the form with an actual `EF-BB-BF` parameter file. The parent independently checked BOM navigation/read-back and clean terminal state on that exact executable, SHA256 `2132230b643d3727b88b089204ab5dfc515ffa7baa5c063a6bf28b8b35eca20f`. Cold readers still made recoverable shell/home mistakes; the guide is a usable workflow, not a guarantee that an agent never miscalls it. Evidence: `final-reader-report.md` and `final-exe-proof.json` in the same run directory.
- Source and Windows packaged-executable behavior are tested separately. The existing installer payload already carries `pea.exe`; this work did not install an MSI or certify PATH delivery. Packaged browser workers explicitly refuse non-Windows SEA execution; other-platform lifecycle support remains unverified.
- Canonical `pnpm verify` on the combined cutover/evaluator tree belongs to the cutover parent. This lane ran focused checks and package builds. Direct Pea/mcps package compiler invocations still report errors in unchanged transitive runtime/host files; they are not reported as green.

The next useful investment is the next real product regression and its exact invariant. Add shell convenience or richer observation when a concrete task exposes the friction; copying the upstream command inventory would not advance the correctness goal by itself.
