## Decided

- 2026-09-16: A pod is one folder of plain source: scripts with declared entrypoints, JSON members, assets. Typed JSON is reusable data. A library owns the operation and the domain validation; storage knows no domain rules.
- 2026-09-16: Composition (`$include`, `$preset`) stays. The user's own standards use 271 directives across 76 files, and fragments are the only way to manage a standard. `$schema` is the only member-level selector; typed filename suffixes are removed because 142 of 150 real members have none.
- 2026-09-16: Publish vendors, it does not precompose. Every consumed foreign fragment is copied under `settings/_vendor/<pod-id>/...` and the reference is rewritten to `@local/_vendor/...`. A published pod composes from its own bytes only, so it never needs a sibling pod. Vendored files are the inspection copies.
- 2026-09-16: Local foreign references (`@global/...`) resolve by the installed pod whose manifest `id` matches, with no hash pin. Two matches fail and name both folders. Folder names remain addresses, never identity.
- 2026-09-16: Identity is three facts: folder address (physics), manifest `id` (lineage, a stored human claim), and per-file SHA-256 (derived, never stored). Pod content hash is derived on demand. `requires`, `parent`, `origin`, and `release.json` are removed because each is a stored claim about bytes elsewhere and needs reconciliation code to catch drift.
- 2026-09-16: Provenance is one `imported.json` receipt written at import: archive hash, locator, date. It is non-semantic, excluded from the content hash, never validated, never gates execution.
- 2026-09-16: Pod-level preparation gates only manifest structure and entrypoint source. JSON members validate individually when used, by the library the `$schema` names. One bad member never hides the pod's other members from a product route.
- 2026-09-16: Validation lanes stay separate: structural schema runs in the host with ajv and works offline; composition and semantic validation run through the native bridge and appear when a Revit session attaches. Web-only editing without Revit is schema-checked only, on purpose. C# libraries are not hosted outside Revit.
- 2026-09-16: One member editor (form and raw JSON are two modes of one draft) is embedded in the product routes as the apply-source panel. Capture creates a new member and lands in place with it selected. The Pods route is a browser that opens the same editor.
- 2026-09-16: `/schedules` keeps both verbs on separate affordances: "push" writes cell values, "apply" writes a schedule definition from a member. Capture of a schedule is spec only, never cell values.
- 2026-09-16: Capture always creates a new member. Apply requires saved content. Preparation is an internal snapshot step, not a user-facing stage or artifact.
- 2026-09-16: APS is the sole authority for parameter definitions; execution retrieves current definitions. Failed pagination cannot return a partial snapshot. APS is never bundled in a pod.
- 2026-09-16: Documents/Pe.Tools holds preferences.json and Pods/<local folder>. Hard replace, no migration code. Cache, credentials, installed binaries, and transient state live elsewhere. Outputs and receipts live under the pod's excluded output directory.
- 2026-09-16: A member is addressed as `{ pod: <manifest id>, path: <relative path> }` everywhere. `$schema` alone says what a JSON member is for, resolved by the host's `settingsSchemaProvider` mapping.
- 2026-09-16: Schedules get `schedule.capture` and `schedule.apply` bridge ops mirroring the family pair. Desktop palettes stay as the quick Revit entry for family manager, family migrator, and schedule manager; they call the same ops as the web routes.
- 2026-09-16: Family and families apply write the same pod receipt as schedules, into the current pod's `output/<run>/`: pod id, member path, member SHA-256, op id, plan hash, outcome, output references.
- 2026-09-16: The host is the only reader of the pod folder. It composes one member through a per-member bridge prepare and passes composed JSON inline to plan and apply.
- 2026-09-16: Pea reads and edits members through the settings document ops and applies through the same route commands as the UI.
- 2026-09-16: The Pods route is the thinnest view over op-projected data: browser, member editor, receipts. Script pods keep `entrypoints` and `PeScripts.csproj`; JSON-only pods need neither.
- 2026-09-16: Plan is the confirmation sheet of Apply, never a stage or page. Only `/families` needs a real plan because it runs an expensive bulk operation that cannot be rerun cheaply. Schedules have no plan: apply creates a new schedule every time.
- 2026-09-16: Normalization shape S2, "one route kernel": one route definition (entity, target kind, schema, capture op, apply op) drives `/family`, `/families`, `/schedules`; engines expose one outer edge (`Capture`, `Apply`, and `Plan` where needed); palettes and bridge ops are adapters over it.
- 2026-09-17: One thread binds one Revit document. "A single thread should only have one canonical document bound." The thread head is the one target store; every product route and every chat pane reads and writes it; the URL carries the thread, and a `?target` pin is a view, never a second store. A second document is a second thread.
- 2026-09-17: The audit stage is a live read of the target's entity into an in-memory draft; capture and apply are "save this draft as a member" and "write this draft to Revit". A pod appears at save, not at audit. One draft shape per entity serves the audit table and the spec editor; on schedules, cell values are a section of the spec that capture omits.
- 2026-09-17: A draft is thread-owned Work, not route-owned page state. Pea proposes into it from chat without the route being open; the inline chat card renders the same proposals band the route renders. "User asks to rename a param across the entire project, then the inline rendered proposal in chat surfaces it to the user, and the user can open the route to see. That is my dream."
- 2026-09-18: Composition retains the exact consumed root and dependency bytes once; effective JSON is a decoded view and never source-byte authority.
- 2026-09-18: Family build/apply and schedule apply write immutable `input.json` evidence plus byte-exact `effective-input.json` before native effects, and receipts retain both paths for admitted outcomes.

## Owed

- Page logs across Pages (owner queue 10, kaitpw: important). Today no `pe.js` door reads another Page's log, and the raw `page.state` route (`GET /pages/:slug/state`, `ts/packages/host-contracts/src/pe-api.ts:993`) checks no caller. Why it matters:
  - The need is real. Row 9's cold prompt asked a new document-profiler Page to show "the latest saved Profile reading", which the first Page had kept. Pea could only re-run the census and keep a second log (`<run>drive/f1/C1b/REPLY.md`). A Pod with a census Page and a report Page meets this every time, and two logs of one reading drift apart.
  - The open route is a live boundary gap. Any Page's script can read any other Page's whole event log, in any Pod, by fetching that route. Event logs hold model readings and a person's actions.
  - The product is sharing. Pods move between people on the firm drive, so a coworker's Pod runs beside your Pages. While Pages are same-origin with the app (SEC-1), that Pod can read your logs, and the route's missing check is not the only open door.
  - Pea is taught around it, not protected from it: `ts/packages/mcps/tests/pea-pod-knowledge.test.ts:51` bans teaching `GET /pages/`, and the skill says a Page's log is its own.
  - Next step: decide the door, a typed same-Pod read or none. Then make `page.state` answer only its own Page's minted caller and the person. Page isolation is rejected (queue 12), so this refusal stands on its own: either `page.state` checks its caller, or the route stays open by decision.
- Cross-home root isolation (owner queue 13, ADOPT). A hung root `lstat` or `readdir` in one Pods home makes an admitted healthy Page in another home answer 503 after 5 s, proven by three red probes (`root-io.test.ts`, `<run>purger/REVIEW-fa689643.md`). The firm drive's root scans took 6 to 12 s in the A9 log. Rule: a request for an admitted Pod in one home resolves from the last completed census of a slow home and never waits on its root listing. W44 is building it on `pp/home-root-isolation` (a2922a98 keeps the red probes).
- CONN-CAP (owner queue 14, enabled later). Every Page iframe opens its own EventSource (`ts/apps/host/src/pages/pe.js:621`) beside the shell's one stream (`ts/apps/web/src/host/resource-stream.ts`). The host serves HTTP/1.1 (`ts/apps/host/src/app.ts:302`), and a browser allows 6 connections per origin, so 4 Pages in one shell or a few tabs stall every further request with no error. A13 saw 9 connections and a fourth tab that never finished loading. There are three candidates. Serve each Page from its own `*.localhost` origin, which needs no certificate, with a spike owed. Hold one SharedWorker stream per origin. Or serve HTTP/2, which needs local TLS for 127.0.0.1. Item 12 is rejected, so Pages stay same-origin and a fourth candidate opens: the shell relays its one stream to its Page iframes over postMessage.
- ID-ADMIT (REVIEW-3401491f F-D45-1). A cold request, or a neighbour Pod that is new, renamed or whose manifest changed, walks that neighbour's members, so a named read costs O(P + changed neighbour members). A readable twin `pod.json` whose `index.html` open fails EBUSY loses its identity claim, and the requested Page still answers 200. Next step: admit identity alone before uniqueness and member selection, with an identity witness apart from the complete witness. `readFolder` and capture join the three today (`<run>purger/REVIEW-3401491f.md:19`, `:25`). One Pod's metadata timeout also recaptures every Pod for that request (HANG-REUSE).
- WIT-CPU. The discovery witness CPU work is O(all cached member rows and serialized bytes): `ts/apps/host/src/pod-disk-signature.ts` partitions, parses and re-serializes the whole prior witness on each pass, though filesystem work is scoped. Next step: keep the witness per Pod, already parsed, and serialize only the changed Pod's group. Add phase durations (root lstat, root readdir, slowest Pod) to the scan-end line too (T-PHASE), because A9b's 7,071 ms field scan is unattributed.
