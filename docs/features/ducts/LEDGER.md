**Physics and pricing**
- One loss engine, the TS `ducts-domain`, shared by host and browser. Pe computes every loss; Revit's own ASHRAE route computes 0 on most fittings (`WHY-NOT-REVIT.md`). Each duct carries the sum of the grilles downstream; duct friction from length, size, flow and roughness; each fitting C × velocity pressure from ASHRAE grids by a family:type rule; each grille's path is the sum from its fan; the worst path is the fan's ESP.
- 2026-10-20, kaitpw: computed results are not persisted. The route recomputes fast enough; schedulable result parameters come only when a schedule asks for them.
- 2026-10-21, kaitpw ("agreed"): fan airflow never enters the path sum (a fan's flow is the sum of its grilles by definition, as in RHVAC); the unit-airflow input matters only for a second unit in the same network whose air does not end at grilles, such as a side-stream dehumidifier. `PE_M_Fan_AirFlowDesign` is not asked for anywhere else.
- 2026-10-21, kaitpw ("on board with all of this"): fan or passive is proposed by rule C: a person's ruling, else Revit base equipment, else a value in the unit-airflow slot makes a fan; passive only for a through-flow device (every duct port the same classification) when another unit moves air in its network; else fan. A fan with no stated flow takes the derived sum of the grilles it serves (shown, never written). Several fans in one network price per fan: each fan owns its stretch until its air meets a bigger fan's; the header shows the worst fan; passive units pass air through and merge the networks on either side. PROVEN[deterministic, saved Project A snapshot]: 0 multi-fan blocks, 322 terminals priced, the same as before the change.
- 2026-10-21, kaitpw: a loop modelled in Revit is usually intended (SA 22's round takeoff feeding a parallel branch) and never blocks; it is flagged in Diagnostics as "priced as a tree", cut where the walk reaches a joint a second time. A loop closed only by one of Pe's inferred joins still blocks with "break the join".
- 2026-10-20, kaitpw (product-direction meeting with the firm's leads): manufacturer pricing of terminals is unscoped from the ducts product. Terminals are finalized at the very end of a project, and in residential work the installed terminals rarely match the specified ones, so pricing them early can mislead. A terminal is priceable, never required: with a drop in its slot it is priced; without one it prices as zero, sits in Diagnostics as "not priced", and never holds Write. It still supplies its target airflow.
- 2026-10-20, kaitpw: effective length is the working unit. Feet are the main number, each loss converted at its own duct's friction rate (the RHVAC way), total effective length and ESP in in-wg in the header, the design friction rate in settings because it is the same everywhere. The critical run is picked by pressure; feet at each duct's own rate do not track pressure exactly (SA 24: a 664 ft branch beside a 592 ft critical run). kaitpw 2026-10-21: "analysis is what we need, not sizing".
- Manual D and ASHRAE are two methods, not two organisations disagreeing: Manual D turns a fitting into equivalent feet at a design friction rate for hand sizing; ASHRAE multiplies a coefficient by the velocity pressure at the actual speed. Straight-duct friction should match RHVAC closely; fittings differ for a methodological reason.
- The tree reads the same bridged, staged network the header prices; an unpriced value never displays as 0.000 (it reads "no drop" with the reason); rows are named by type, not family; units are labelled from the firm's `PE_G___TagInstance`.

**Network building and healing**
- Groups are Revit-connected components computed before any inference; the tolerance pass then bridges. Near-miss (under 1 in, same air type, facing, centred) and stretched (1 to 2 in, off-centre, onto a capped end, inside a body, an inline accessory) joins are bridged, priced and final, listed only in Diagnostics with "object"; anomalous joins (reversed connector, a part through its host, mixed air types) block until ruled; different air types never join silently. kaitpw 2026-10-20: more inference, fewer repairs; asking about every sub-inch join trains click-through.
- 2026-10-20, kaitpw: verdicts on open ends and inferred joins heal the model instead of living as Pe metadata, because a JSON blob is a second source of truth and a user of another tool would see a different network. Heal what we can; what is left shows plainly and blocks only when it breaks the calc.
- 2026-10-20, healing closed: `ducts.heal` (`DuctHealer.cs`) caps a dangling end with the duct type's own cap (sized and rotated by hand, taking the duct's phase), connects coincident ends (≤ 1/16 in) and closes a same-size collinear gap ≤ 3 in (union, else extend); everything else is a person's "fix in Revit" row. Each item runs under Pe's own post-check (connected, sizes equal, origins within 1/16 in, system unchanged), because Revit reports "connected" even 13.7 in off; preview commits inside a rolled-back transaction group; apply is one transaction per network. The planner never pairs two ends already in the same Revit-connected group (a bend read as a gap, fixed 2026-10-21). PROVEN[session, controlled `pe.app-25`, dev lane, R2025, Project A copy]: SA 22 healed 2 caps, re-read clears both ends.
- 2026-10-21, "make <unit> the fan of <system>" (`ducts.assign-fan`, Revit's Select Equipment): an existing system takes a base equipment by removing the unit connector then setting `BaseEquipmentConnector`; refused when the unit's port belongs to another system or the system already has a fan. **Where every value lives (the residency rules)**
- 2026-10-20, kaitpw: Pe products manage Revit state. Important inputs and rulings are backed by Revit, preferably parameters on the element, so another tool and another user see the same thing; Pe adds the agent bindings and a convenience UI. Pending, unwritten edits are the only Pe-held state.

Firm defaults (`PE_M_Grd_AirFlow`, `PE_M_Fan_AirFlowDesign`, `PE_M_Fan_ExternalStaticPressure`, `PE_M_Grd_ExternalStaticPressure`) sit in code marked `// firm-default:` until they move out.
