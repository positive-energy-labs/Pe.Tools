## The one generated registry

`apps/host/src/routes.generated.ts`, emitted by `codegen:routes` through `apps/web/scripts/route-registry.ts` (`renderRouteRegistry`, on this branch, unit-tested, not yet wired). Its type is `RouteRegistryRow` in `apps/host/src/route-registry.ts`:

```ts
export interface RouteRegistryRow {
  readonly key: string;        // module.data.key
  readonly folder: string;     // apps/web/src/<folder>
  readonly address: string;    // module.data.address
  readonly contract: string;   // router.contract ?? key: the address table row
  readonly dock: boolean;      // router.dock: the web renders null at this address
  readonly closure: { fingerprint: string; envelope: BuiltinClosure };
  readonly host: HostRouteModule;   // data from the closure, work projection, reads and leaves from <folder>/host.ts
}
export type RouteRegistry = Readonly<Record<string, RouteRegistryRow>>;
```

The emitted file holds one static import per route for `../../web/src/<folder>/host.ts` (where the declaration names one) and for the closure JSON, then `export const routeRegistry: RouteRegistry = { ... }`. Static, because the host is packed by rolldown (`apps/host/vite.config.ts` `pack.entry`) and run under `jiti/register` in dev (`apps/host/scripts/dev-watch.ts:64-68`): neither follows a glob or a computed import. The web needs no generated registry: Vite expands `import.meta.glob` at build and test time.

Why host-side and not web-side: a single file cannot statically import both a route's browser module and its host read without one build reaching the other's code, which the two build guards forbid. The host registry imports only `host.ts` files; the web glob imports only `route.ts` files.

## Contract for the route directory

A builtin route is one directory, `apps/web/src/<folder>/`, plus its C# op:

- `route.ts`: the declaration (`export const module = route({...})`, `export const router` when the address differs from the key). `host: "./host.ts"` names its own reads, relative to the declaration. A route whose reads another route owns (session-admin reads `open`'s) names no `host`.
- `host.ts`: host-only. Exports `reads` (and `leaves` when it has them) built with the evaluator's `read(name, { input, output, run })` over the contracts in `reads.ts`. Moved from `apps/host/src/reads/<key>.ts` with `git mv`. Helper modules a read needs move beside it (`fan-sheet.ts` and `ducts-design.ts` into `ducts/`, `families-matrix.ts` and `families-outcome.ts` into `families/`, `rooms-plan.ts` into `rooms/`, `schedule-outcome.ts` into `schedules/`). `fans/host.ts` imports `../ducts/fan-sheet.ts`; the measure counts directories the author's diff touches, and a fans author touches one.
- `reads.ts`: neutral. The read contracts `{ key, endpoint, input, output, axes, demand? }` the browser parses with at runtime (`apps/web/src/shell/typed-mount.ts:195,207` parse `read.input` and `read.output`; `shell/host-read-source.ts:25,29`). `host.ts` attaches `run` to the same object; `route.ts` passes the same object to `hostRead`. The capability type is `typeof reads.sheet`: inferred, never mirrored. The three hand mirrors in `packages/agent-contracts/src/*-read.ts` are deleted; their schemas move to `reads.ts` or stay in contracts as schemas only (no `*Capability` object).
- `apps/web/src/<folder>/*.generated.ts`: none. `source-closure.generated.json` is build output and stays untracked.
- The directory's `icon` is any Lucide name. The generator refuses a name that is not a key of `lucide-react`'s `icons` export (1737 names at `lucide-react@1.21.0`); `AppRoute.iconKey` is `string`; `catalogue.ts` resolves `icons[route.iconKey]`.

## Defaults, re-openable

- **Registry home is the host** (`apps/host/src/routes.generated.ts`); the web discovers with `import.meta.glob`. Alternative: a web-side registry with lazy `() => import("./host.ts")` edges, rejected because the web bundle would ship host chunks.
- **The address table keeps the projected field type** (`z.fromJSONSchema` plus a type string from the JSON schema, as the stubs do today) in one file. Alternative, `typeof import("apps/web/src/<folder>/route.ts").fields`, makes contracts compile web sources (JSX, React types). Re-open when a neutral `fields.ts` per route exists.
- **`reads.ts` is a third file in the directory**, not a type-only import of `host.ts`, because the browser parses `read.input` and `read.output` at runtime (`typed-mount.ts:195,207`). Re-open if the shell stops parsing on the browser side.
- **A shared read has one home**: `session-admin` names no `host`, `open/host.ts` registers `open.*`. Alternative: the registry dedupes identical module imports, as `hostReadPaths` does today.
- **`$route.tsx` is one dynamic-segment file**, not a splat, so the `design-system_.*` satellites keep priority. A two-segment builtin address would need its own file; none exists.
- **`generated/<key>-work.ts` and `<key>-graph.json` stay** in 5a. They are projections the host and Pea read, not registries; ADR 0035 rule 4 names them nowhere. Owed to the routes ledger: fold the work projection into the registry row once `route.ts` has a neutral work export the host can import.
- **The icon check runs in the generator**, which has `lucide-react` in `apps/web`; contracts stays React-free. `route-icons.test.ts` checks every tracked directory row against the library, and is red on this branch for a real reason: `apps/web/src/home/route.ts` declares `icon: "Home"`, which `lucide-react@1.21.0` no longer exports (`House` is the name), and today's closed `ICONS` map silently renders nothing for it. The C2 writer renames it; that is the one-word proof that the library check catches what the closed list missed.
- **`host.ts` is the route directory's read module**; the guards scope by the presence of `route.ts` in the same folder, because `apps/web/src/route/host.ts` and `apps/web/src/scene/host.ts` are kernel browser modules (the host client) that share the name.
