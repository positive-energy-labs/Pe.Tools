# pages ledger

An agent or a person drops a folder of HTML under the product home and the host serves it at an open URL with doors into Revit: typed ops, show, captures, the thread target, and shared state. Captures are the one picture currency that every surface links. Source: muse rounds 1 and 2 of 2026-10-04 over the pressure-drop walkthrough (`.artifacts/pdrop/walkthru/`, gitignored) and the synthesized-views session of 2026-09-28.

## Decided
- 2026-10-04, kaitpw: arbitrary HTML is non-negotiable. A page is a folder with `index.html`. There is no typed page document and no required template, because diagrams, todo lists, cheatsheets and issue trackers each want their own UI, shaped by the user.
- 2026-10-04, kaitpw: a page is served at an open URL (`/pages/<slug>/`), never only inside an iframe. An agent can then drive it with chrome-agent, both parties can write the same fields, and the page is a control surface and a shared scratchpad.
- 2026-10-04, the home is `Documents/Pe.Tools/Pages/<slug>/` beside Pods. One root holds product pages and repo throwaways. It is outside git, so a page over an NDA model is safe by location. No registration: a dropped folder appears.
- 2026-10-04, kaitpw: agents use the raw host endpoints and the curated MCP tools alike, so a page's doors are the same vocabulary as `pe_find`, `pe_read` and `pe_do`, with the same capability keys, and a utility earns a place only when it is very common or hard to get right first try. `pe.js` is therefore `find`, `read`, `do`, the target headers (bridge session and document from the thread head), the read-versus-write door (`/call` versus `/actions`), and `state`. Show and capture are keys, not functions. `pe.css` serves the house tokens, opt-in. `pe.target()` and `pe.css` are the default head; a product route that wraps a page with the Situation head is deferred until a page asks for it.
- 2026-10-04, shared state is the page kit kernel's event log (`.claude/skills/slot.page/kit`), persisted by the host per page. The page appends with `fire`, an agent appends over HTTP, the host fans out over SSE, and the page writes its own snapshot after each fire so an agent reads state without running the reducer.
- 2026-10-04, kaitpw: no approval ceremony on page-originated mutations. "approvals are unnecessary and i think probably harmful at the end of the day, they'll be to hard to make a real feature that actually applies at all the edges it should, and at the end of the day its just ceremony." A page button that mutates Revit runs as a human act, and the receipt carries origin `page:<slug>`. For pages this defies the `AGENTS.md` posture line "Agents propose; users retain approval"; the wider reading is Owed.
- 2026-10-04, captures are the one picture currency. `revit.context.view-image` is promoted: durable storage under the product state directory, one blob per sha, one receipt per taking (request, document, view, focus ids, registration, taken-at, origin `human`, `agent` or `page:<slug>`), a linear `/captures` route newest first, and `capture` as an inspectable kind. A chrome-agent screenshot registers the same way. A page shows a capture with `<img src="/captures/<sha>.png">`.
- 2026-10-04, phase 1 as built (feat/pages): the host keeps every successful `revit.context.view-image` through `/call` in one product-wide store, `<product>/state/captures` (not per host service, so a dev host and the installed host serve the same `/captures/<sha>.png`). The blob is the hash of the bytes; a registration whose sha disagrees fails the call and keeps nothing. Origin comes from the `/call` attribution: a `web:`/`page:` origin header, else the actor header (`agent`), else `human`. `capture_view` answers small text (URL, receipt id, view, size) and no pixels: the Pea MCP server stringified the media block into 763k characters and no model saw an image (pages-pre proof, 2026-10-04).
- 2026-10-04, the ladder a page climbs: a folder; doors; a manifest (`page.json` gives a front-door tile, the `page` inspectable kind and a chat card); shared like a Pod; promoted to a route through `protoui` and `close`. A page shows its rung by what it contains, never by registration, and is never silently product. The page skill's stand-in law applies at every rung.
- 2026-10-04, pictures are for people and tables are for Pea (spatial ledger: table before pixels; the synthesized-views session: images were Pea's weakest sense). The Space renderer stays that session's scope.
- 2026-10-04, phasing (counsel, delegated by kaitpw): 1 captures; 2 pages served with doors, proven by rebuilding the pressure-drop walkthrough on them and deleting its server; 3 manifest, chat card and the two Pea skills.
- 2026-10-04, phase 2 as built (feat/pages; `ts/apps/host/src/pages-route.ts`, `src/pages/pe.js`, `src/pages/pe.css`): `GET /pages` lists every folder under the root that holds an `index.html`, newest first, and names `root`, so an agent learns where a page lives; a browser gets a list page. `GET /pages/<slug>/[file]` serves the folder (`index.html` by default; dot-files are refused, so `.state/` is private; a slug is letters, digits, `-` and `_`, so there is no `..`). `GET /pages/<slug>/state` is `{ seq, events, snapshot }`; `POST /pages/<slug>/events` appends one JSON object and answers the row (`seq`, `at`, `origin`, `event`); `GET /pages/<slug>/events?after=N` is SSE from N then live, with a `ping` event every 15 s; `PUT /pages/<slug>/snapshot` keeps the page's own state. The log is `<slug>/.state/events.jsonl` beside the page, so deleting or sharing the folder takes its state along. Origin is `x-pe-origin` when sent (`page:<slug>` from pe.js), else `agent` for the agent actor header, else `human`. The route is a plain web handler mounted through `HttpEffect.fromWebHandler`, so its tests need no server and SSE is a `ReadableStream`. `pe.js`, `pe.css` and the product's `base.css` are read beside the source on the dev lane (an edit is live) and staged to `<exeDir>/pages` by `stage-web.mjs` when installed.
- 2026-10-04, `pe.js` is one classic script and one global. `pe.target()` picks the session and document (`?session=&doc=` or `?title=` on the page URL, else the one connected session and its active document) and sets `pe.doc`. `pe.find(words)` is a word match over `/ops`. `pe.read(key, request)` is `/call`. `pe.do(key, input)` tries `/call` and, on the host's 409 `notDispatched`, admits the op through `/actions` as a human act with a document destination, polls the receipt to settlement and answers `result`. A capture URL that rides the `x-pe-capture-url` header is copied onto the answer as `captureUrl`. The host's refusal text is the error message, word for word.
- 2026-10-04, `pe.state(k, { local })` makes any kit kernel's log shared: it replays `/state` from the kernel's base (so the URL's view keys survive), tags every later fire with `eventId` (never `id`, which pages use for their own things), posts it, follows the stream, writes the snapshot 150 ms after any change, and keeps `nav` and the `local` types in this copy. A shared event carries no view state: the walkthrough's `add` no longer selects the added checkpoint, because a replay on another copy was moving that copy's selection (seen 2026-10-04).
- 2026-10-04, the stream is owned by a watchdog, not the browser: on error, when it never opens within 10 s, or when no heartbeat arrives for 45 s, `pe.state` replaces the EventSource from the last seq seen and the host replays the gap.
- 2026-10-04, the walkthrough rebuilt on the doors (`.artifacts/pdrop/walkthru/index.src.html`, built into `Pages/pdrop-walkthrough/`): "show in Revit and read live" is `revit.context.show-elements` then `revit.detail.elements` with the key parameters named, 0.4 to 2 s; "deep read (script)" is `scripting.execute` with the census parameter walk (stored loss tables, connector flows, system facts), which also makes or refreshes the "PDROP walkthrough" 3D view and answers its id, 3 s, admitted through `/actions` as a human act (receipt `scripting.execute succeeded human document`); "save my Revit selection" is `revit.context.summary`. Notes, added checkpoints and readings are shared; selection, busy and errors stay local. `serve.mjs` and its `.cs` templates are deleted; the README says how to run it. PROVEN[session `pages-p2` (snapshot, R2025, Chadds detached copy, windowed, controlled) + browser (three T3 preview tabs: two copies of the walkthrough and the todo page) + deterministic (`apps/host/tests/pages.test.ts`, six tests) + `kit/check.py` (15 steps), feat/pages, 2026-10-04T19:05Z to 19:30Z; evidence under `.artifacts/runs/pages-p2/` in the pages worktree]. Proven there: a page's add, note and reading reach the log with origin `page:<slug>`; a second copy sees a note the instant it is typed; an agent's `POST .../events` appears in an open page; a host restart under three tabs (vite origin) and a later agent write arrive without a reload; a capture taken with `x-pe-origin: page:pdrop-walkthrough` lists with that origin, and the focused capture shows the selected fitting in the walkthrough view.
- 2026-10-04, in the dev loop a page's stable origin is vite (`http://127.0.0.1:5174/pages/...`), which proxies to whatever port the host claims; a host restarted while its old port lingers comes back on a dynamic port, so a tab pinned to the host's own port cannot reconnect. The installed lane has one port.

- 2026-10-04, phase 2 second drive, the pressure-drop tour (`Pages/pdrop-tour/index.html`, outside git): a first-time agent's rebuild of the walkthrough on the doors alone, no kit build step. One ReadOnly script finds a worked run (the top-flow grille of a mid-sized supply system, then the air-carrying members of its duct network by rising flow, equipment last), `revit.context.lens` boxes a 3D view around it, and each stop shows in Revit, reads live through `revit.detail.elements`, and on a fitting sets Specific Coefficient and reads back. - 2026-10-04, what the second drive pushed into the doors, each one a workaround the page had to carry first: `pe.kernel(reduce, base, render)` (the ten kernel lines every page copied); `pe.script(source, { mode, timeoutSeconds })` (scripting.execute's ceremony: permission mode, status, and a compile or runtime failure thrown with the compiler's line instead of a succeeded row carrying `CompilationFailed`); `revit.context.lens` (the walkthrough's view block as an op: Mutate, 'Pe lens' by default, 4 ft padding, Medium and HLR, links, levels, grids, rooms, spaces and zones hidden; answers the view id for `revit.context.show-elements` and `revit.context.view-image`); and a 'Make one' recipe on `GET /pages`, so the front door says how to make a page, not only which exist.
- 2026-10-04, Revit facts the tour hit, kept here so the next page does not rediscover them: `MEPSystem.Elements` is terminals and equipment only, the ducts and fittings are `MechanicalSystem.DuctNetwork`; a tap hangs on a duct's face, not on an end connector, so a connector walk cannot cross it (order the network by flow instead); `Connector.Flow` throws on a connector without flow calculation; `Document.Regenerate()` outside a transaction is refused; the Chadds document shows pressure at two decimals, which hides every fitting loss (convert to in wg with four).
