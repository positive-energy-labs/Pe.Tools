First-class user world

Mesa is a reserved truth, not a simulated feature

The Pea factory constructs only one strict descriptor today: local root, storage.kind = "local-unversioned", and isolation = "none". The visible badge says exactly what that means. Shared and serving schemas deliberately admit a reserved mesa-versioned descriptor so the future wire has a clean slot. A valid descriptor can reach the serving app; this does not provide a mount, auth, checkpoint, isolation, or version-control implementation.

Why no mount exists

WSL2 has /dev/fuse and fusermount3, but this machine has no Mesa CLI, credential/config, current mount, or bwrap. Pea has no @mesadev/* dependency. The released SDK mount() returns an in-process filesystem, not an OS path.

The real gate

Pin answering bytes; authenticate; create a Linux FUSE mount visible in findmnt; read and write through it; checkpoint; inspect diff/history; tear down; reopen and prove persistence; then run Pea commands inside bwrap against that same mount.

Stop condition: all eight rows must pass as one round trip. FUSE plumbing alone, downloaded tarballs, Git copy/sync, symlinks, or the SDK virtual filesystem do not count.
