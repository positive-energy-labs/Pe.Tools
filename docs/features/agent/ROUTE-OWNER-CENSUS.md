# Route owner lifecycle census

## Scope

This source-only census covers every `useRouteOwner` and `createRouteOwner` caller under `source/pe-tools/apps/web/src`. It assumes the stated React 19 `<Activity mode="hidden">` behavior: React keeps state and DOM but cleans up effects while hidden.

`createRouteOwner` owns mounted atoms, Reading subscriptions, action state, and an activity log. Its base state is `busy`, `failure`, `conflict`, and `log`; `runAction` also holds the in-flight flag, elapsed-time interval, and stop callback (`source/pe-tools/apps/web/src/route/use-route.ts:100-141`, `source/pe-tools/apps/web/src/route/use-route.ts:143-220`). `dispose` marks the owner permanently disposed, clears the busy interval, and releases every mounted atom and inspector subscription (`source/pe-tools/apps/web/src/route/use-route.ts:223-263`).

## Test-only callers

`source/pe-tools/apps/web/src/route/use-route.test.ts` calls `createRouteOwner` directly at lines 37, 54, and 71. Each test creates an isolated owner for action-stop behavior, failure retention, or idempotent disposal, and each disposes it explicitly (`source/pe-tools/apps/web/src/route/use-route.test.ts:36-75`). These callers hold no user state and do not mount a React subtree, so Activity hiding cannot affect them.

The grep also finds the declarations at `source/pe-tools/apps/web/src/route/use-route.ts:100` and `source/pe-tools/apps/web/src/route/use-route.ts:278`; they are definitions, not callers. Imports in `data-tables.tsx`, `store.ts`, and `provider/view.tsx` are covered by the runtime rows above.

## Why the delayed cleanup does not protect Activity

`useRouteOwner` stores one owner in a ref and installs one effect. Cleanup schedules `store.dispose()` with `setTimeout(..., 0)`, while the next effect setup cancels the timer (`source/pe-tools/apps/web/src/route/use-route.ts:277-290`). This covers an immediate cleanup/setup cycle such as the intended StrictMode double mount. Activity hide has no immediate setup, so the timer runs and disposal becomes permanent. Activity reveal retains the ref and returns the same disposed store. The effect can clear only a timer that has not fired; it cannot recreate the released mounts or reset `disposed`.

## Conclusion

1. All three runtime `useRouteOwner` sites are broken if React 19 Activity hides their subtree.
2. `useRoute` loses route Readings and owner action state, although its React `page` and `outcome` state remain.
3. Data Tables keeps its React draft, but it loses the owner that tracks apply status, failure, conflict, and activity.
4. Chat loses its owner-held composer draft, attachments, pane selection, lens selection, scroll intent, World state, timers, and action state.
5. The one shared fix seam is `useRouteOwner`: it must distinguish true component unmount from Activity effect cleanup and call `store.dispose()` only for true unmount.
