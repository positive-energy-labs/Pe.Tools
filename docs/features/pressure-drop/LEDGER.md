# Pressure-drop ledger

The surface that makes a firm model compute duct pressure drop: a grille-first drawer where fitting losses are set by type rule, Pe computes the critical path and fan static pressure, and values are written into Revit so they travel with the model. Campaign evidence (a real client model, NDA) stays gitignored under `.artifacts/pdrop/` and `.artifacts/runs/`; the 2026-10-14 Codex run is mined into `.artifacts/runs/pdrop-muse/` (main checkout).

## Decided

- 2026-10-04, Revit's arithmetic is right and its automatic fitting route is dead. PROVEN[session, controlled `walkthru`, R2025 detached copy]: straight duct matches a hand calc within 0.1%; "Coefficient from ASHRAE Table" computes 0 on every duct fitting in R2025 and R2026; "Specific Coefficient" is exact. One small supply system hand-set end to end: Revit critical path 0.1105 in wg against 0.1107 by hand.
- 2026-10-04, root cause of "nobody fixes it": the number has no reader; the state is invisible; it is per-instance with no type default; the default reads zero with no error; and the largest term is the grille's catalog drop. The product creates the reader and makes the state visible.

- 2026-10-04, kaitpw: Pe computes the critical path itself (no placed air mover, whole system, or drop-accepting family required); Revit's number sits beside it as the check that the model has become whole.
