1 · Six nouns

A route author learns these and nothing else. Three are data, one is capability, two are projections.

NounKindDefinitionHome
TargetdataWhere a call runs. host, a session, or a document named by {session, openId}. An openId is one open lifetime minted by Revit; close and reopen mints a new one. A thread stores a default Target request; a call may override it and never rewrites it.agent-contracts/src/target.ts CUR
WorkdataThe persisted, revisioned JSON a route and the agent co-edit. Schema, write mask, commands. Writes carry expectedRevision. A Reading never writes into Work; an operation's status never advances Work's revision.agent-contracts/src/route-state.ts, route-doc.ts CUR
ReadingdataAnything observed from Revit, the host, or disk. One subject, one observation time, one lifecycle: absent · loading · ready · stale · failed. Readings arrive on one stream with gap frames. Dead words, with the noun that replaced them: Scope, Document, World, Verb, Feed, Lane, Link, Slot, Bound, Multi, Stage, Store, Resource, fixture. A grep for any of them in apps/web/src outside a Revit or file-system sense is a defect.

2 · Laws

  1. The empty manifest is valid. A route with only key and name renders its name and the host lamp. The primitive never demands a Target, Work, or Actions.
  2. A default is not an execution target. A call resolves to resolved · checking · choose · failed. choose never picks another session. The host re-validates the openId at dequeue and refuses with 409 if it closed.
  3. Everything else is a projection. If a value can be computed from Target, Work, Readings, and Page, it is not stored. The URL, refusals, the targeting sentence, stages, and the help overlay are projections.
  4. No invalid states. Delete every runtime guard and the types still refuse the bad state. A surviving guard names a type to fix.
  5. One registry, one stream. One AtomRegistry per app (ADR 0009). One EventSource per page. No component opens a connection. docWriter reads the registry synchronously and POSTs; nothing sits between a click and the revision that click is guarded by.
  6. Two lifetimes. Work outlives a Revit process; a Reading and an operation's Target do not. Mount identity includes the route instance so two panes on one document keep separate Page.
  7. At most once. A request id is reused on retry, never regenerated. A lost acknowledgement is unknown, recovered by the same id, and is never an invented success.

3 · The manifest

Static, at module scope, one per route file. Every field after name is optional. Keys are const generics so demo ids and chords are unions, not strings.

interface Route<W, R extends string, P, A extends string> {
  key: string                                    // URL segment, agent tool prefix, atom key prefix
  name: string                                   // head line
  needs?: "session" | "document" | "project" | "family"   // absent = host only; drives the head sentence
  work?: WorkSpec<W>                             // zod schema, write mask, commands (route-state.ts)
  readings?: Readonly<Record<R, ReadingSpec>>    // subject kind per key; file kind carries id + zod
  page?: z.ZodType<P>                            // one record; default = the schema's default
  actions?: Readonly<Record<A, Action<W, R, P>>>
  views?: readonly View<R>[]                     // key, label, draws; a JSON view is a View
  seeds?: Readonly<Record<A, Seed<W, R, P>>>     // total once declared; a missing key does not compile
  docs?: ReactNode                               // orientation prose; the only prose channel
}

interface Action<W, R, P, I = void> {
  label: string
  says: string                                   // one sentence for a stranger; the agent tool description
  needs: "host" | "session" | "document" | "project" | "family"
  actor: "any" | "human"
  input: z.ZodType<I>
  dirties: readonly R[]                          // Readings invalidated on success
  chord?: Hotkey                                 // @tanstack/react-hotkeys literal type
  ready: (ctx: Ctx<W, R, P>, input: I) => string | null   // refusal sentence, or null
  run:   (ctx: Ctx<W, R, P>, input: I) => Promise<void>
}

interface Seed<W, R, P> {                        // one moment; Layer-free
  title: string
  work: W
  readings: Partial<Record<R, unknown>>
  page: Partial<P>
  failure?: { action: string; message: string }  // failure injection for the demo lane
}

Ctx is what ready and run receive: the resolved Target, Work with its revision, every Reading's current state, Page, and a host caller bound to that Target. Actions never import React and never close over render state. The agent consumes the same record through the capability catalogue.

File readings. {kind: "file", id: SettingsDocumentId, content: zod} yields raw, token, parsed, parseError, and drift: fresh · stale · conflict · gone. Edits stage in Work as pointer patches; the user's file never receives route state. Save checks the token that was reviewed. No watcher, no lock. CUR PROOF demo-lane.scenario.test.ts settings seeds

4 · Wire

Branded strings are validated, server-issued ids, not security boundaries. The host checks every reference. CUR in target.ts, reading.ts, action-receipts.ts.

type DocumentRef     = { session: SessionId; openId: OpenId }
type DocumentRequest = { kind: "open"; ref: DocumentRef } | { kind: "named"; session: SessionId; address: Address }
type CallTarget      = { needs: "nothing" } | { needs: "session"; target: SessionId }
                     | { needs: Document-ish; target?: DocumentRequest }         // omitted = the turn's default
type Resolution      = { kind: "resolved"; target: ExecutionTarget } | { kind: "checking" }
                     | { kind: "failed"; message } | { kind: "choose"; reason: "missing" | "session-gone" | "document-closed" | "wrong-document-kind" | "ambiguous" }

type ReadingRequest  = { kind: "work"; route; scope } | { kind: "inventory" } | { kind: "receipts"; ... } | { kind: "file"; id } | { kind: "<route>-reading"; target: DocumentRef }
type ReadingFrame    = { kind: "snapshot"; key; value } | { kind: "failure"; key; error } | { kind: "event"; key; value } | { kind: "gap"; key }
type Reading<T>      = { state: "absent" } | { state: "loading"; requestId; deadline; previous? }
                     | { state: "ready"; observation } | { state: "stale"; previous; reason } | { state: "failed"; message; previous? }

type Receipt         = { state: "running" | "succeeded" | "failed" | "unknown"; id: RequestId; target: ExecutionTarget; ... }
type ThreadHead      = { revision: number; defaultTarget: DocumentRequest | null }   // frozen into a Turn at admission

A response for a previous Target cannot land in the current Reading. A response started before a known invalidation cannot erase it. Reconnect reacquires snapshots; gap frames diagnose loss and never substitute for reacquisition. Session identity is one branded string; the broker id already hashes pid and process start, so incarnation is inside it.

5 · Address and lanes

?demo=<action>demoMounts seeds[action] in an isolated owner with its own registry and receipts. The demo can write. It is the deterministic proof lane and the design-system catalogue's source. Replaces ?source=fixture. CUR PROOF apps/host/tests/demo-lane.scenario.test.ts, 21 seeds
?work=<id>liveA Work identity that is not document-scoped: a saved Takeoffs capture, the Instances workspace. Not a lane.

Seeds are declared where fixtures were worth keeping: takeoffs, family, families, chat, settings, instances. Every other fixture dies with no seed. A route may declare no seeds; once it declares one it covers every action.

6 · Surfaces, keys, help, inspector

  • Head. One component for every route: the name, the host lamp, and, when the manifest has needs, the targeting sentence with its picker. Outlier routes get the name and the lamp. CUR as route/shell.tsx.
  • Keys. Three tiers, one registration shape. A manifest action's chord is bound by one loop in route/keys.tsx; a pane's shortcuts are bound by Pane scoped to its focus; a widget binds its own. Every registration carries meta: {name, description, tier, region?, refusal?} through keyMeta(). A chord with a refusal fires and speaks the sentence, never silently ignored: a route chord on the outcome line, a pane key on its card. No root manifest exists; the root tier is a word in the meta until a navigation chord needs one. CUR
  • Help. The page (Alt+/) measures the rendered panes, reads every registration back from TanStack, and joins them by region: manifest chords in a band above, pane and widget keys on cards with leaders to their region in the chart, the route's docs prose below. No hand-written keymap exists. CUR route/help.tsx
  • Door. One control beside the head opens keys, views, docs prose, and, in dev builds, the inspector.
  • Inspector. Dev only. For every declared value: owner, subject, readiness, revision or token, active request, and the Action that last changed it. Exports the current moment as a Seed. It has no write channel into production state. CUR as route/inspector.tsx.

Chat hosts other routes as panes. A hosted pane is a second route instance with its own Page and its own Target request; it shares Work and Readings by subject key, never by store. Cutover is for compile only: no route gets a new UX decision in this pass.

9 · Folds

Delete, then fix; the compile errors are the map. One writing line per fold, one commit per fold, in this order.

  1. Contracts. resource.ts becomes reading.ts with typed subject keys; scope.ts collapses into target.ts (thread default is a DocumentRequest); Action gains chord, says, dirties; Seed type lands.
  2. Web primitive. One Route manifest type, one shell (head, door, keys, help, inspector), one useRoute(manifest) hook over the registry. targeting/model.ts, actions.ts, kit/*, flow.tsx, host/route-target.ts, host/target.ts, the ten refusal symbols in route-store.ts die.
  3. Readings replace Query. @tanstack/react-query removed; the 36 useQuery sites become Readings, one-shot lookups as once readings.
  4. Fixtures to seeds. Six seeds land; eight fixture files and takeoff/proto die; ?demo= mounts the isolated owner.
  5. Route cutovers. chat and takeoffs first, then family, families, parameter-links, settings, instances, schedule-grid, ops; outliers get the empty manifest.
  6. Guards and docs. Section 8 lands; the ledger is rebuilt; this page is deleted when every GAP tag is gone.
