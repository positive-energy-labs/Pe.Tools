Three boundaries were killed. Native-only gives element-id soup and misses the firm file. Page-only holds nothing. The kernel reading boundary, counsel's first pick, was rejected by three of four implementing threads because host compositions consume inputs the browser never sees.

## Decision

1. **The recording boundary is the host's input services**: the native bridge, the clock, document marks, firm and catalog files, the action journal and receipt producers, and the capture store. Each is a swappable Effect service (ADR 0029 rules 3 and 4). A recording source answers them. A replay never reaches a live input, and a miss is a typed refusal, never a fall-through to live. Process-global inputs become services first.
2. **A taking is the event.** Every input a body consumes becomes a taking: content hash, time, coverage and an outcome kind, `answered`, `refused` or `unknown`. A replay that lacks the outcome kind turns a recorded refusal into a fabricated success. Observations are stored once by SHA-256 over kind, output version and canonical bytes. Repeated identical reads stay distinct takings. A computed result has two ids: a recipe id (body fingerprint, ordered named dependencies, args) for reuse, and a content hash for verification. A bundle carries its build stamp and catalog hash and refuses a mismatch.
3. **Epochs.** An epoch is a named point per document: `afterWrite(receipt)`, `synced` or `captured`. It holds a cursor range of takings and the bindings (instance, reading, args hash to taking) that record what each mounted pane showed, so a refresh under a point re-serves the same taking and an ambiguous match refuses. Basis is `live`, `point` or `compare(point, live)`. A past view is tinted, read-only and labelled "Recorded Tue 3:10pm"; compare to now is one toggle. kaitpw is neutral between "yesterday's model" and "the last time I looked at this fan", with the simpler one as the tiebreak.
4. **The History rail lives in the app shell.** It lists the named points and derives from the Timeline (ADR 0030 rule 11) and the epochs. A route writes nothing for it.
5. **Capture is automatic, local and bounded.** It is a kernel policy on events, never a route call, and it refuses when full (ADR 0029 rule 15). kaitpw: "saving to disk or what have you should never be a routes concern in principle." Sharing is always explicit, under publication consent with a named scope. ADR 0018 governs egress only, so local recording is not blocked by it.
6. **Users can only read a recording.** The plan is shown and marked "historical, cannot apply". Editing values on a recording, to see what the UI does, is a developer-build feature (ephemeral Work on a point). kaitpw: "Users can never do it."
7. **A plan runs on a recording; rehearse and apply are refused.** kaitpw: "preview often idempotently validates against revit ... then preview and apply should be fully disabled, since inherently the reading they edit on is old ... I think refuse should be it. the apply means nothing if it doesn't faithfully emulate the real expereince as installed on a user machine. for those cases you can escalate to testing on a real ... pe-revit sdk session." Restated: a plan is a Read (ADR 0030 rule 4) and runs over recorded inputs. A rehearsal validates against the current model, which a recording cannot answer honestly, so rehearse and apply refuse with the reason "needs live Revit". Testing a write flow goes to a controlled `pe-revit` session. Plain calculation still runs.
8. **Keyed diff identity.** A diff key is a stable key with a kind, never an element id: `UniqueId` for elements; `ElementPort(UniqueId, connectorIndex)` for fan ports, open ends and connector references; `SystemName` for systems. A section has no element. It is keyed by its bounding junction connectors, not by a hash of its sorted member set, because a heal cap or a split changes the member set and would diff as delete plus add. A path is keyed by (fan, terminal). Loops need a canonical cycle id, still Owed. Work cells keyed by element id today (`terminalDrops["14088043"]`) map to `UniqueId` before any diff. `_PE_DuctLosses` is one JSON parameter on Project Information, so diff facets reach into its keys instead of reporting "Project Information changed". Cross-document correspondence exists only through a saved registry held as a Work member (the RHVAC Compare precedent), never invented from equal strings. A diff is `Incomparable` when either side's coverage is partial. Deletes come from a full id-set difference, never from Revit's change feed alone. A diff keeps model facts, authored inputs and computed results apart. "What changed since yesterday that affects FC-23" needs three sides, as computed, recomputed today and live, and both walk sets.
9. **The cloud seam is ready; cloud waits.** kaitpw: "cloud waits, nothing for that exists yet. but seam should be ready. and maybe even stubbed out with full contract." Restated: one `CloudProvider` contract now, with identity, consent, scope (bytes, metadata, pictures, source fragments), bundle format, chunk, get, list, publish, commit, reconcile and errors; one stub implementation that refuses every call. No scheduled upload. A real backend is a drop-in implementation with no change elsewhere.
10. **Step order, honestly priced.**
   1. Services first. The journal, log, clock, marks, firm and catalog files and capture store become swappable services. The bridge bypasses route through the shared read join. The failure channel becomes one typed union (ADR 0029 rule 5), so refusals and unknowns can be takings. The fixture boolean becomes a Lane union, `live`, `fixture` or `recording`. The one canonical Work handle lands before recording, so "Work in memory" is not a fourth binding. The fresh-worktree dev start is fixed. This step is large. It serves routes; on a recording Pea may use only the catalog reads the bundle holds, and a script is never recordable because its answer depends on its code.
   2. A recording source behind the Lane: load a bundle, answer by binding, else by the unique candidate, else refuse; show the provenance badge; the capture policy writes bundles. This covers two worktrees on /fans against yesterday's Chadds with no Revit.
   3. Epochs and the History rail (`?at=`), read-only.
   4. Keyed diff with coverage.
   5. Recompute with today's engine, per body marked recomputable only when every input goes through the context.
   6. Cloud: an explicit consented export of an epoch bundle; scheduled pushes only after a grant ruling reopens ADR 0018.

## Consequences

- A route author adds `keyedBy` once per entry and nothing else; History, Diff and the badge are the shell's.
- Provenance: every value says live, recorded at T, or recomputed now from T's inputs. Pea gets `source` in every payload; the badge is for people.
- Step 1 does not retire OUTSTANDING A17 (its write step, native readback and Pea turns need Revit), and A15's number belongs to MUAS-1 `14577391:2`, not FC-23 (`.artifacts/runs/evolution-20261103/OUTSTANDING.md`).
- Risks: capture completeness is bounded by the bypass migration, so early recordings are honest but thin; a whole-document cloud Chadds snapshot once exceeded the 16 MiB bridge frame, so bundles chunk.
- Rejected: recording at the kernel reading boundary; native-only and page-only boundaries; plan-only previews on a recording as validation; a new noun (Frame or Epoch as a noun; an epoch is a Timeline cursor plus bindings); git-ancestry baselines in the product; collapsing equal bytes into one taking; a standing cloud grant; a route-called capture verb.
- Open, none changes the shape: the default home of a cross-document correspondence (Pod member or local Work member); an explicit "accept baseline" verb.
- Every stake is a source read; no runtime claim. The dev-start failure is FALSIFIED in the browser-dev lane only.
