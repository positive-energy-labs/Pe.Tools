# Root run consent and shared Work

## Context

Human-only commands, agent-only proposals and thread targets imposed different authority on the same tool. A harness spawn token also lacked causal turn identity. Looking up the current turn at delayed tool entry could authorize an earlier invocation under a later turn.

This decision supersedes the Pea grant and authorship policies in ADRs 0016, 0017 and 0021. It extends the independent tool and conversation model in ADR 0022. The workshop's uncommitted per-write hold draft was not adopted.

## Decision

Human and Pea share Work edits, optional suggestions and semantic commands. Expected revisions, schema validation, exact identity and current native evidence govern both authors. The host stamps provenance. Observation, readback, consent and retirement have trusted contracts that raw Work patches cannot write. An explicit cutover preserves original persisted bytes and historical uncertainty.

The harness owns one consent decision per root run. The first consequential command opens a 60-second countdown. Allow now or the deadline authorizes subsequent writes in that root run, across documents and resource types. Explicitly delegated descendants inherit the host-issued root binding. Independent and scheduled runs receive separate consent. Human presses supply consent for their command.

ActionJournal remains the execution owner. It records immutable normalized intent, destinations, source versions and captured Work before waiting. Preparation follows consent. Consumed inputs and native basis are revalidated before effects, including at native queue dispatch. Receipts retain the allow decision. A recorded step alone does not establish native dispatch. Unknown native outcomes require recovery.

Normal completion closes new admission and permits already-authorized bounded commands to finish. Unapproved waiting commands cancel. Stop writes also cancels unstarted effects. Per-command cancellation does not stop other commands. Restart never grants expired runs consent.

Each turn resumes the saved ACP conversation in a fresh child process with one immutable host-minted run token. Its MCP and CLI descendants inherit that token. No current-run lookup relabels delayed invocations. Full/bypass mode selection is removed. Unjournaled native mutation approvals refuse. Adapter modes are not a universal filesystem sandbox.

Effects come from registered semantic definitions or generated native metadata. Cache invalidation is not authority. Scripts include sibling documents in their footprint. Page and external-device trust adapters remain explicit and separate from Pea's run consent.

Bootstrap alignment remains a human administration command because it changes the machine's add-in installation. A read-only SDK verification freezes its exact installation subtree; the SDK owns filenames, manifests and pruning. Directory effects also exclude concurrent file writes below that root. Account sign-in and third-party trust administration retain their explicit human boundary.

Semantic Apply owns planning, validation, apply, readback and conditional retirement. Preview remains optional. Turn completion notices derive completed and still-running work plus exact Work links from durable owners.

## Consequences

Process startup and session resume add per-turn overhead in exchange for causal identity without modifying the upstream inference loop. Deterministic adapter tests cannot prove real-provider filesystem confinement or native Revit behavior. Those proof limits stay explicit.

The same consent provisionally covers Pod source, settings, other user files and publication. The countdown is an intervention opportunity, not proof of informed content review: most users cannot read JSON, and beta editors have incomplete routing and resource coverage. The policy revisit and deferred escape from shared child consent remain in the agent ledger.
