# 0033: One host read graph; History is what the host published

Date: 2026-11-06. Status: accepted. Source: kaitpw's rulings in thread f20de09f ("Rethinking Kernel Provenance Architecture"), after a zoom-out with three source-read lanes: census, cleanroom design and adversary (`.artifacts/runs/kernel-crusade-20261104/takeover/A-census.md`, `B-cleanroom.md`, `C-adversary.md`). Amends [ADR 0028](0028-seven-nouns-two-clients-one-catalog.md) (nouns, local-ok engine) and [ADR 0031](0031-recording-at-host-input-services-history-in-the-shell.md) rule 3 (bindings) and rule 10 step 1 (Work migrations). Every claim below is a source read at c730b36b; no runtime claim.

## Context

kaitpw's goal for the kernel: "give every hard thing to every route for free. I should be able to prototype any new product, of similar conceptual complexity to fans or ducts or families, easily, without having to worry about all the small features that make a UI trustable and predictable." And: "I want to boil every ocean we can see ... I want to never think about it again."

The terrain does not meet that goal. A pane receives data through 18 named source-to-pane chains, and Fans uses 16 of them. The kernel and runtime hold 46 identity, version or freshness families. Five separate gates guard the one late-reply failure. A Fans-level route touches about 902 integration lines in five files and borrows 1,160 more. The route schema has six reading kinds (`use`, `work`, `derive`, `worker`, `port`, `feed`, `ts/packages/agent-contracts/src/route-kernel-data.ts:65-77`).

The browser assembles pane data itself. It merges system batches (`ts/apps/web/src/ducts/sources.ts:120`), assembles the sheet from an overview and 3 + P detail calls (`:224`), and prices ducts (`ts/apps/web/src/ducts/kernel.tsx:26`). Because recording happens on the host (ADR 0031 rule 1) and History needed what the pane showed (ADR 0031 rule 3), the browser had to carry signed ingredient receipts back to the host. The receipt and acknowledgement substrate is payment for that split.

## Decision

1. **One host read graph.** A read is a typed host function. It reads native leaves, files, the clock, Work and other reads through one tracked context, and the graph records every dependency. A read returns a Value: immutable data plus its evaluation reference, coverage, origin and freshness. Domain composition and domain calculation happen only inside reads. One read convention replaces the six reading kinds.
2. **The browser renders.** A pane shows one semantic Value from a host read. The browser owns rendering, Page pose and selection, hover, focus, gesture preview, draft text in a cell before commit, retained old values with their status, and one generic gate that drops a reply for an old subscription generation. The browser does not merge route data and does not run domain calculation. The `local-ok` browser engine allowance in ADR 0028 is deleted.
3. **History is what the host published.** A History point records which Value versions the host published for each subscription at that point, plus Page state. No browser acknowledgement of accepted bodies exists. No signed provenance tag travels with data. kaitpw: "yes, occam. Im not sure i see the utility in option 2 at all as far as the users felt experience goes." This replaces "what each mounted pane showed" in ADR 0031 rule 3. A point can name a version the browser has not decoded yet; the gap is milliseconds and nobody feels it.
4. **Public nouns: Capability, Work, Value, Route, Pod.** Page is client state inside Route. Timeline and History are kernel projections. Reading, StateCell data contract and catalog entry fold into Capability and Value.
5. **No legacy migrations.** kaitpw: "NO LEGACY! we are moving too fast, and dont have any users, so migrations are not worth it. work should simply be deleted." A stored Work whose schema changed is deleted, not converted. A future migration seam is welcome; performing migrations now is out of scope. Route-by-route conversion tables in the runtime are deleted.
   2026-11-07: a refuse-and-keep amendment was proposed and overruled by kaitpw; rule 5 stands.
6. **Pod code isolation on the host is deferred.** Pod reads run on the host. A sandbox for them is not a starting-line feature. Recompute claims stay limited to reads whose every input goes through the tracked context.
7. **No route-specific code in the kernel.** A kernel file does not name a route, a route's request type or a route's file. The current violations are deletion targets: Ducts-only retained bodies in the shell reading API, the `ducts.sheet` export kind in recording, firm and duct-catalog members on the generic file service, `FansOwner` in the host root, and the Families refusal in the generic Work result.
8. **Fans is the exemplar.** Fans moves first. Its integration code target is about 150 lines.

## Consequences

- Dies: HMAC body receipts (`ts/apps/host/src/body-receipts.ts`), the accepted-reading acknowledgement wire and `acceptedPointPolicy` (`ts/apps/host/src/recording-points.ts`), browser body-receipt carriage (`ts/apps/web/src/ducts/sources.ts:214-279`, `PeReadings.acceptReadings`), the accepted-slot registry, the prerequisite hybrid on `t3/recording-points-contract`, browser source factories that compose route data, the legacy reading scheduler, and `ts/packages/runtime/src/work-cutover.ts`.
- Survives: the host input services and Lane union, the observation store and takings with answered, refused and unknown outcomes, recipe ids and read-set graphs, durable point ranges, keyed diff core, cold-lifetime ownership repair, caller admission, the Work journal and handles, the ActionJournal, consent, plan seals, StateCells, the catalog and linker.
- Freshness does not go away. A read that makes several Revit calls must check one document mark across them and refuse a complete Value when the mark changes.
- The legacy route cutovers (ADR 0031 step order and the routes MAP step 8) wait until the read graph lands, so each route migrates once.
- Risks: the evaluator is one shared piece, so a bug in it breaks every route. kaitpw counts that as the point. The tracked context must be enforced, not agreed on, or replay claims are false.
- Rejected: a browser acknowledgement of the accepted version; browser-side composition with signed receipts; a browser engine beside the host engine; converting stored Work.
- Kill gate: a spike that makes the Fans sheet one host read and runs the late-reply, mixed-basis and refused-batch falsifiers (`B-cleanroom.md`, "Falsifiers before adoption" 1 to 3). If the evaluator cannot fence Revit freshness across several calls, this ADR reopens.
