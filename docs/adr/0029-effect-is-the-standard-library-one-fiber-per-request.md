## Context

The host uses Effect as a library for the bridge, not as the standard library. At c510da4b: 3 `Context.Service` declarations, 0 `Effect.fn`, 71 `Effect.run*` calls of which 4 are at a process edge and 60 are inside the host between Promise code. Each mid-program `runPromise` ends the fiber: the scope closes, interruption stops, services are re-provided per call (`NodeServices.layer` rebuilt at 16 sites), and a typed failure becomes a thrown `Error` whose only identity is its message (`bridge.ts:622` picks cancelled or failed by regex). Lifetimes are ambient: `ActionJournal` and `HostLog` are module `let` singletons, `RunConsents` runs the ADR 0027 consent window on `setTimeout` against `Date.now`, harness children die by `taskkill /T`, and `Date.now` is read at 240 sites. kaitpw does not trust any cancellation the product attempts today, and cannot try undo of Pea writes or a different permission model across threads and tabs, because no owner of lifetime exists.

Effect at the edges only (a decoded frame, a typed bridge client) is better than none. Effect in the middle, with Promises on both sides, is worse than none: every boundary pays the cost of both worlds. The cost is per boundary, so the number of fiber ends, not the fraction of Effect code, is what makes adoption all-or-nothing.

## Decision

1. **Effect is the standard library for the host, the MCP server and the web's doors.** Processes, files, paths, HTTP, config, schema, time, collections, tracing and testing come from Effect modules. Hand-rolled code where a module exists is a finding.
2. **One fiber per request.** A request, a tool call, a bridge frame, a harness event enters a fiber at the edge and stays on it until it answers. Every spelling of the run family (`Effect.runPromise`, `runSync`, `runFork`, `runPromiseExit`, `runCallback`, the `*With` forms, `runMain`, aliases, destructures and computed access) is legal only on a line that carries `// effect-edge: <reason>`, and the `pe/effect-edge` lint refuses every other site. The reason comes from a closed vocabulary: `process-main`, `als-crossing` (retires in phase 5), `cli-main`, `test-runner`, or `island, phase 5`. An island is a per-file count in `ts/tests/repo-guards/src/effect-islands.baseline.json`, and that baseline only shrinks; nobody edits a count upward. The "four edges at c510da4b" (`host-program.ts`, `app.ts`, `request-identity.ts`, `packages/browser/src/keeper.ts`) were an inventory, not a whitelist; two of them were fake edges and phase 3a deleted them.
3. **Dependencies are services.** Anything with a lifetime is a `Context.Service` built by a scoped `Layer` and provided once in `hostProgram`: `RevitBridge`, `ActionJournal`, `HostLog`, `RunConsents`, `HarnessThreads` with its spawner, `MachineOwner`, `CaptureStore`, `ReceiptExport`. Module-level `let` state standing in for a service is a finding. A test swaps a layer, never a module.
4. **Nothing ambient.** Time comes from `Clock`, children from `effect/unstable/process`, files that need a scope from `FileSystem`. `TestClock` proves ADR 0027's consent window. Persisted timestamps (the `at:` on every event and decision) come from `Clock` through `DateTime`. Exceptions, recorded here because Effect falls short: `node:os` for `homedir` and `hostname`; native realpath for worktree identity (Effect's `stat` has no `ino` above 2^53 and `realPath` keeps 8.3 names).
5. **Failures are values.** Expected failures are `Schema.TaggedError` in the type (`Refused`, `CommandRejected`, `StepFailure`, `BridgeError`, `NoRevitSession`, `Cancelled`); the router maps a TaggedError to HTTP once, in one place. A `throw` inside an Effect, and a regex on an error message, are findings. `Cause.pretty` inside an error message and text classification of a response (`classifyEndpointFailure`) are findings that phase 5 deletes. Plain `_tag` classes are allowed only until the file they live in is converted.
6. **Name the steps.** A reusable effectful function is `Effect.fn("name")`, so every step is a span. `Effect.fnUntraced` is no longer the house idiom. The trace is the telemetry seam: `receipt-export.ts` reads spans, not hand-placed `record` calls.
7. **The edge is a Schema.** Every boundary the host does not author is decoded, never cast: the thread store (`events.jsonl`), harness child config and probe responses, CLI discovery, the web's harness SSE frames and tab memory, MCP takeoff blobs. Effect Schema owns these. Transport metadata is inside the decode boundary: the SSE `lastEventId` is decoded with its frame, and the resume cursor moves only after the frame is accepted. The `fromStandardSchema` bridge (zod under Effect) is deleted in phase 8; until then its import count only shrinks, and a new edge uses native Effect Schema. zod stays the contract kernel (route graphs, verbs, catalog, Pea projections) until the schema wave below.
8. **Schema unification is a later wave, now unblocked.** MCP SDK v2 (`@modelcontextprotocol/server` 2.4.0, landed c510da4b) takes Standard JSON Schema, and Effect 4.0.2 emits it through `Schema.toStandardJSONSchemaV1(Schema.toStandardSchemaV1(S))` (PROVEN[compile, 2026-11-02]). The zod kernel (266 files) moves to Effect Schema in its own wave after this one, with two known deltas to rule on: Effect's JSON Schema for numbers and optionals is wider than zod's, and `additionalProperties` differs between beta.92 and 4.0.2.
9. **Where Effect does not fit, and why.** `ducts-domain` is pure values in, values out; wrapping it adds nothing. React render code stays React with `effect/reactivity` Atom; `Effect.gen` in a component is a finding. `eventlog`, `workflow`, `cluster`, `KeyValueStore` and `TxRef` are rejected as a second owner of state beside the journal. `Schedule` owns in-process backoff only (machine poll); the journal owns retry across restarts because receipts must survive one. `Path` is adopted where a scope is needed, not for every `join`.
10. **Every route declares one of three lifetimes.** A route receives no raw launch capability; its shape decides who owns the work.
    - *Request-owned read*: the work lives on the request fiber. The fiber dies, the work dies.
    - *Durable command*: ownership transfers to the journal at submission. The response can return before the work ends, and losing the client does not stop the work.
    - *Subscription*: the route observes. Losing the observer never stops the turn.

    A native Revit read is a durable dispatch owned by the bridge scope and joined by request fibers, through one `NativeReads` service. Its identity is the schema-encoded input with sorted keys; this is the only definition of read identity, and the browser has no second one. Joiners are refcounted. When the last joiner leaves interrupted, `NativeReads` sends a cancel. A typed refusal (for example over-budget) goes to every joiner as a typed failure. The entry is forgotten on settle. A receipt names one cancellation outcome: `never-dispatched`, `native-cancel-requested`, `native-acknowledged`, `committed`, or `unknown-until-reconciled`. A cancelled request fiber is never reported as a cancelled Revit write.
11. **The serial slot.** A session runs one Revit op at a time, in FIFO order, with no priority and no preemption. Interrupting a waiter removes that waiter from the queue and does nothing else; it never releases a successor. `op.cancel` never takes the worker permit: it goes out of band to the running op. The slot is released only when Revit answers or acknowledges a cancel. Browser abort signals are not assumed to arrive at Node (PROVEN 2026-10-31, geometry-perf thread); the join in rule 10 is the protection.
12. **Supervision.** Every forked fiber (consent window, poll, probe, dispatch) is forked into a service's scope with `Effect.forkScoped` or `Effect.forkIn`. A detached `runFork` is a finding. A settlement operation (consent, queue release) is one typed operation: a persist failure or a listener failure cannot strand a waiter, and cleanup settles every waiter.
13. **Tests serve invariants, not coverage.** kaitpw, 2026-11-02: "pls do not treat tests like something crucial to keep ... might prefer if we ended with less coverage and less tests ... move to pe-browser tests more ... i HATE units". Restated: unit tests are not a preservation target. When a module converts, its Promise tests are deleted, not ported. A deterministic test stays only when it guards a consequential invariant that the browser lane cannot falsify: the consent window on `TestClock`; settlement fault injection; A/B/C queue interruption, including "cancel passes the permit"; runner teardown; native-read sharing (`native-read-sharing.test.ts`, `slow-capture.test.tsx`) until the pe-browser gate of the geometry-perf thread is green. pe-browser is the target lane. The 70 test islands go with their tests.

## Consequences

- Cancellation becomes trustworthy per lifetime (rule 10): a browser disconnect interrupts a request-owned read and retires a queued op that has not dispatched; a durable command continues under the journal; a dispatched op gets a cancellation outcome from Revit, not from the transport. Host stop closes one scope that kills every child and flushes the journal. This is the ground that undo of Pea writes, cross-thread and cross-tab permissions, and a different Pea permission model need before they can be tried. The phase 5 acceptance protocol is the proof; until it runs, the claim is UNPROVEN.
- `docs/features/host/EFFECT-V4-PATTERNS.md` sections that contradict this ADR carry a "superseded by ADR 0029" note; the doc keeps the v3 to v4 gotcha table.
- The `effect-edge` lint and the shrink-only per-file island baseline are the ratchet together. The lint alone says only "each one has a comment"; the baseline says "fewer than before".
- Island census at 36f76766: 74 product islands and 70 test islands, beside 6 declared edges. Product clusters: A `bridge.list` session lookup 21, B `bridge.invoke` 20, D provide-per-call 10, E log 7, C request body 5. Root cause: Effect for the bridge client only, so every Promise caller paid a `runPromise`. Expected trajectory of product islands: 74, then 71 after 3a (39f9dc7d), about 55 after 3b, about 0 after phase 5. End state of edges: `process-main` and `cli-main` only.
- `invokeBridge` (`bridge.ts:98`) and every Promise adapter over a service are deleted in phase 5, not adapted.
- Pin: effect 4.0.2 (landed c510da4b). `effect/http`, `effect/unstable/process` and `effect/reactivity` are `@stability unstable`; the pin is exact and a bump is a wave of its own.
- Rejected: shape 2 ("services, handlers stay Promise"), because each service still needs a `runPromise` adapter per caller and the 60 sites move without going; shape 4 ("everything Effect now, including the zod kernel and a SQL-backed Work store"), because zod is the catalog's JSON Schema source until the schema wave re-bases the Pea projection.
